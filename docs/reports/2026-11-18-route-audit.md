# DeskWeft 路线审查与迭代 · 2026-11-18

基线 `90389f3`。审查对象是一个本地 DeskWeft 服务、多个使用它的客户端，以及随包 Skill。主控负责跨层复现和集成，审查、实现、独立操作者和代码复核子任务均使用 `gpt-6.2-sol`。没有部署客户端或迁移用户记忆。

## 发现与处理

| 层 | 复现的不足 | 这次改了什么 |
|---|---|---|
| 记忆写入 | 两个客户端读同一份旧方案，分别用 `overwrite=true` 写回均成功；后一笔抹去了前一笔新增的失败记录。 | 使用原有 revision，在同一服务的写锁内做条件覆盖。Skill 要求更新时传 `expected_revision`，冲突先重读、合并事实；旧式覆盖仍兼容。 |
| 记忆读取 | 选一条路线前先收多份正文；定向打开后仍夹带其他路线的「未解决」。继承方案给出续读位置，却拒绝用原键续读。一个非 UTF-8 文件还能阻断其他健康记录的查询。 | `recall(非空查询, max_body_chars=0)` 只返回路线摘要和元数据；选定后只读该方案。继承键在续读中保留 revision 和零信任等级。损坏记录单独报错或警告，不替用户改写。 |
| MCP 观察 | 只想找原生编辑框时，却必须同时取截图和 UIA 树。客户端说明还把只读调用描述成不会打扰前台。 | `see(native_only=true)` 在已有 worker 内限量列出原生子窗口，显式报告截断，不截图、不读 UIA 树。原有默认截图和 `with_tree=true` 保留。客户端说明区分工具的许可检查和实际前台保护。 |
| MCP 定位和分页 | `$control` 参数与主目标的身份校验不一致；`find_items` 遇到单项名称 7000 字符时返回自己的起点。 | 参数复用唯一目标解析，无法证明唯一则不调用成员；父窗口和后验矩形校验保留。超长首行保留部分结果，再探测后续；尾行若只是本页预算不足，保留数据和错误供下页重叠核对。 |
| Skill 选路 | 用户已给出完整导出仍被引去找窗口；已知现有 QQ 实例和任务不适用于新实例时，隔离预检仍排在前面。 | 起步先核对授权来源的批次、范围和必需字段；能交付就不启动 GUI，只补缺口。已有原生句柄、需要原生枚举、确实需要 UIA 三种情况分开。先判断隔离路线能否服务当前任务，再决定是否预检。 |

## 验收证据与边界

- **回归基线与复测。** 改前 461 项中有 1 项失败：版本阶梯测试读取了本机实际 Edge 目录，却断言固定版本。改成受控输入，目录枚举本身仍由临时目录测试。改后 `python -B -m unittest discover -s tests -p "test_*.py" -q` 通过 491 项；Skill 元数据、文档中的 MCP 示例和 `git diff --check` 通过。运行仍有既存的测试 socket ResourceWarning 和工具 schema 弃用提示。
- **本机 Win32 夹具。** [可重跑的脚本](../../tests/live_native_observation.py) 创建从不显示的父窗口与两个已知的 `EDIT` / `STATIC` 子窗口。进程内 MCP 客户端通过真实 worker 调用 `see`：上限 1 返回 1 行、截断为真；上限 2 返回两个已知句柄、截断为假；两次均只有文本块。最后销毁夹具并核对句柄失效。没有操作用户应用或连接已安装 HTTP 服务。
- **临时记忆与离线替身。** 20 条合成路线的默认响应包含 6000 个正文字符；目录响应有 20 条摘要、零个正文。选 `route03` 后只返回它的正文和它的缺口，不带其他 19 条。独立复核用同一服务的两个 MCP 客户端按同一旧 revision 写不同正文，一方成功，另一方得到 `stale plan`；读回为胜方正文。另用替身检查列表分页、控件身份不明时拒调 provider，用临时记录检查坏编码和继承续读。字符数不是速度指标，替身不是应用兼容性实测。
- **独立操作者推演。** 仅提供随包 Skill、参考和情境。操作者直接交付合成 B-17 导出的三个状态，变更一行批次后只交付两项；在禁止截图和 UIA 时选择原生枚举而不是全树；在二十条候选记忆中只打开相关一条，revision 改变就从头读，前提不变不重复无进展滚动。这验证的是文档是否足以做决定，不是 GUI 实测。

## 真实应用验收：当前客户端与工作区的差异

2026-11-18 在本机确认 `127.0.0.1:8765` 只有一个回环监听，归属安装目录 venv 的 `-m deskweft.server` 进程。对它和工作区进程内 MCP 分别做 `tools/list`：两端都是 18 项，但不能互换。

| 契约 | 当前客户端 / 已安装 HTTP | 工作区 MCP |
|---|---|---|
| `see` | 无 `native_only`；不能把默认会截图的调用当成只列子窗口 | 有 `native_only`，可只列原生子窗口 |
| `remember` | 无 `expected_revision`；不要并发覆盖已有方案 | 可用原 revision 做条件覆盖 |
| `recall` | 虚构键加 `max_body_chars=0` 实得 `ok=false`，原因为 `max_body_chars must be an integer in 1..6000`；旧客户端筛选时用小的正预算 | 相同参数查询不存在的键，实得空 `matches`；前述 20 条夹具另验了非空目录 |

这一步只握手、列工具和查询合成键，没有部署、重启或写用户记忆。以下区分安装身份、窗口枚举和应用字段，不以一层的证据替另一层验收。

### Microsoft Edge：已从真实页面读回计算字段

- **身份和目标。** [验收脚本](../../tests/live_edge_field.py) 在非输入桌面为本机 `msedge.exe` 建立全新的临时配置，核对进程映像、配置参数及窗口归属。该映像的 Windows 文件版本为 `157.0.4341.60`。离线页面只有一个只读库存框，初值为 `not-computed`，页面脚本算 `7 × 15 − 12`；验收端以预先独立确定的 `93` 作比较。因此读文件初值、窗口标题或非空返回都不能通过。
- **原生枚举。** 工作区 `see(native_only=true, max_elements=16)` 返回一个文本块，包含两个子窗，类名为 `Chrome_RenderWidgetHostHWND` 和 `Intermediate D3D Window`。独立 Win32 枚举核对了同一组句柄和类，结果完整，库存标签匹配数为 0。
- **字段读回。** 同一 MCP 客户端和 worker 随后用确切名称和 `EditControl` 定位页面字段，`ValuePattern.Value` 返回字符串 `93`。派发前后均核对真实执行线程的桌面。前两次单独做 UIA 的读取也均得到 `93`。[脱敏证据](evidence/2026-11-18-live-apps/edge.json)
- **独立复跑。** 主控复跑两步联测，仍得到两个原生子窗、0 个标签匹配和 UIA 值 `93`。82 个输入桌面样本和事件钩子记录到 0 次切换、0 个前台或焦点事件。清理后 Job 活跃进程为 0，临时目录已删除。
- **在版本记忆中复用。** 新建并定向读回 `msedge@157.0.4341.60` 下的 `isolated-web-field-read`，rank 为 0。摘要给出字段未出现于原生枚举时转向 UIA 的条件。已有唯一语义定位的任务可直接读取。
- **验收脚本复核。** 新增两项回归，覆盖损坏或非对象的子结果、结果文件和页面文件重名。前者在确认 Job 已清理后回收临时目录，后者保留原文件并在启动 Edge 前退出。全量单测已从 491 项增至 493 项，全部通过。

### QQ 自动登录后的导航按钮

- **启动前的身份。** `QQ.exe` 的 PE FileVersion 与 HKLM 卸载项均为 `9.9.19.35469`。版本目录与 `resources/app/package.json` 均给出构建 `9.9.37-54395`。首次采样时，`Get-Process` 和 `Win32_Process` 查到的 QQ 进程数均为 0。
- **字段选择。** 最初评估的是登录页固定按钮。用户随后明确授权启动 QQ，并说明客户端会自动登录至主界面。主控据此将验收字段改为主界面固定导航标签。随包的 `qq` 模式会做搜索读写，本轮采用只读入口。Skill 的入口说明现已写明登录参数的实际作用和搜索分支的触发条件。
- **读回与独立核对。** 从同一次启动依次读得登录页「登录」和主界面「联系人」。工作区 MCP 的 `app_info` 从子进程参数识别出运行版本 `9.9.37`。独立 Windows UIA 查询核对可见按钮的 `CurrentName` 和角色，再按控件类型与矩形调用 DeskWeft 的 `LegacyIAccessiblePattern.Name`。两个 MCP 请求都没有把待验文案作为 selector 参数。[只读验收脚本](../../tests/live_qq_field.py) · [脱敏现场证据](evidence/2026-11-18-live-apps/qq.json)
- **选路依据。** 主窗口 `Chrome_WidgetWin_1` 的树身份不完整，读取「联系人」在派发前被拒。切到已核实归属的 `Chrome_RenderWidgetHostHWND` 后，真实 worker 取得完整树，返回「联系人」。原生枚举给出的 2 个子窗与独立 Win32 枚举一致。
- **现场观测。** 这次启动和字段核验约 12.3 秒。208 个输入桌面样本和事件钩子记录到 0 次切换、0 个前台或焦点事件。实验 Job 的活跃进程归零，worker 已关闭，临时目录已回收。
- **清理复核。** Job 归零时全机仍有 3 个 QQ 进程，当时仅记录总数。16:37 复核的 4 个 QQ 进程均在原报告生成后创建，属于另一棵进程树，根进程位于输入桌面。原来 3 个的归属及新实例的启动原因无法追溯。本轮保留了后来的实例。探针已补记创建时间和父 PID，复跑可直接比对。
- **在版本记忆中复用。** 新增并读回 `qq@9.9.37` 下的 `auto-login-navigation-read`，rank 为 0。摘要说明自动登录后应等待哪个字段，以及顶层拒绝时该转向哪个宿主。考虑到实验结束后的进程归属缺口，记忆保守标记 `uses_foreground=true`。

## 下一步优先级

1. **要让当前客户端用上新参数，先安排部署窗口。** 部署后重新核对 `tools/list` 的参数和零预算行为，再做端到端复验；只有工具数量相同不算完成。未部署前沿用旧契约，不对已知不支持的参数反复试错。
2. **用耗时决定下一项优化。** 原生枚举依赖共享 worker 初始化，记忆目录减少的是传回模型的正文。若实测瓶颈在 worker 初始化或记忆扫描，再分别评估独立原生通道或磁盘索引。

条件覆盖适用于同一写入服务；没传 revision 的旧客户端仍可无条件覆盖。不要让多个独立服务共享写同一记忆目录。
