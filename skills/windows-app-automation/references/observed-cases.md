# 有条件的现场经验：把反例用在下一次判断

这些是已有报告的有条件观察，不是本次测量。日期、版本、页面、控件和保护条件属于
证据的一部分；不要把成功或失败直接推广为所有版本、所有控件或整个应用。
完整日志保存在开发仓库 docs/reports 与原实验目录，可能不随 skill 安装；本文保留
足以理解操作方向的上下文，不能代替原始证据。主流程见 [SKILL.md](../SKILL.md)。

## 相同 API 在同一窗口内也可能有不同效果

2026-11-09 的 QQ 9.9.37 前台样本中，导航按钮 Legacy/Toggle 返回成功，未观察到页面变化；
搜索结果行 Invoke 和联系人分组 ExpandCollapse 则观察到预期变化。对照 WinForms 按钮
Legacy/Invoke 可使计数器增加。这支持按页面与控件类型缩小结论，不能写“QQ 所有语义动作无效”。

下一步：认定确实是同一业务控件；查原动作状态和业务标志。已经调用过的发送/提交等
动作不能因为缺少变化证据就换 API 重放。可靠证据确认未执行且不会延后执行，才可重新决定。

## PrintWindow 缓存与元素数变化会造成假判定

同轮报告中曾出现元素数从 316 到 166，但真实屏幕未变；也出现 PrintWindow 帧相同而
真实屏幕不同。像素数（例如 779414）只记录这次截图算法观察到的差异，不代表业务操作
正确，也不是现场应达到的阈值。

下一步：优先读搜索结果、消息标识、展开状态、精确字段等任务证据。没有安全的独立
状态通道时保留未验证；工具的捕获帧比较也只能报告捕获帧，不能据此说“窗口没重绘”。

## 页面、宿主与启动条件必须一起记录

历史聊天应用登录页有含 AutomationId 的语义控件，主内容页面却可能只暴露渲染宿主。
该差异只说明已测页面的来源不同；不能由登录页推广主页面，也不能由一个 Pane 推断
无任何原生/Legacy/API/导出来源。UWP 的壳与 CoreWindow 也须分别定位。

下一步：保存当前 page、hwnd/pid/class、过滤/超时诊断和实际启动参数；调查实际内容宿主。
空截图与空树分别处理，截图不可用时继续适用的语义/原生候选。

## 搜索字段的 name 与定位条件可能变化

2026-11-08 的 QQ 搜索实验中，写入后的旧 name selector 曾短暂 no such control；之后
重新读取完整树，确认唯一 ComboBoxControl 才恢复。该样本没有证明 Name 永久改成写入文本。

下一步：保存原值和原目标身份；重读当前元数据，确认仍是原字段。类型 selector 只在
当前完整树中确实唯一且业务身份可核对时使用，不能删掉 name 后取第一个框来覆盖文本。

## 效果正确、端点相同与调用前保护是不同证据

某次 ValuePattern.SetValue 读回相等，但 foreground_changed=true。LockSetForegroundWindow
失败（error=5）的样本没有取得保护；仅禁用已知顶层后，enabled renderer 仍先进入前台，
随后 setter 报错。这些都不能归为合格后台成功，旧路线继续 uses_foreground=true。

下一步：先核验保护覆盖真实目标、renderer 和 dispatch。随包私有桌面 runner 的显式
语义登录、可逆搜索、恢复与清理另有历史证据，适用条件见
[前台保护参考](foreground-protection.md)；不能只 create 一张桌面就认为旧 worker 已隔离。

## flags、滚动与版本证据不要混为一个结论

早期 QQ 记录分别出现无 flag 的 9/0 节点、有条件的 132/130，以及 README 的 128/126，
口径不同。2026-11-09 的新版本又有带 flags 与裸启动的不同样本；它们说明值得核对启动
条件，不提供现场固定节点数。旧 FileVersion 9.9.19.35469 与安装目录 9.9.22-40824 的
差异也说明安装候选不能替代活动版本证据。

下一步：查当前进程参数、实际 exe/子进程证据，再进行任务相关对照。传了端口不等于
CDP 握手成功；重复同一个 feature 不构成新实验。GPU 条件下联系人页未成功进入，
就不能拿那次滚轮结果与另一页比较，也不能由读树结果推出滚动结果。

## 列表与旧失败记录只是探索起点

早期 QQ 样本有滚轮无变化、ScrollPattern 报错/不可滚动以及 1980 人名单未收全；
算法与滚动参数并未全部保留。新版本某组显示 51/93 且只取得部分已渲染行，口径仍需核对。

下一步：确认总数与筛选范围、真正容器、两页新增项目与稳定身份，再调查 ItemContainer、
分页/展开/搜索及结构化导出。不能把 provider reached_end、已选项或一屏名称当业务全量，
也不能按姓名去重后删掉同名人。滚动无进展只停止当前循环，不停止其他合理方向。
